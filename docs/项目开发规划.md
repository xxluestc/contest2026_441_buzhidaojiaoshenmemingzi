# 团队作品开发规划

## ① 项目名称与一句话定位

项目名称：**基于 openvela 的视障随行视觉辅助胸牌**。

一句话定位：面向具有独立出行能力的视障用户，开发免手持视觉辅助胸牌，通过摄像头和语音交互帮助用户在到达目标区域后发现并确认入口、门牌、站点标识和公共服务设施，弥补导航软件与盲杖无法完成具体目标视觉确认的问题。

## ② 目标开发板及选板理由

目标开发板：**ESP32-S3-EYE**。

选板理由：

- 已有 openvela/NuttX BSP 和官方 ESP32-S3-EYE 配置，可把风险从“全新 SoC 移植”转移到应用闭环与系统优化；
- 板载摄像头、数字麦克风、LCD、Wi-Fi 和外部 PSRAM，覆盖视觉采集、语音采集、联网和本地状态显示；
- openvela 现有配置已启用 Camera、I2S、Wi-Fi、LCD、PSRAM 等基础能力，适合按 M1～M10 逐项验证；
- 外接 I2S 音频模块和 GPIO/PWM 振动模块后，可形成适合视障场景的非视觉反馈。

本项目基于现有 BSP 开发，不把 ESP32-S3-EYE 宣称为新硬件平台适配成果。

## ③ 核心功能与硬件能力

| 核心功能 | 用户价值 | 所需硬件能力 |
| --- | --- | --- |
| 系统与设备能力验证 | 确保基础平台稳定、资源可测 | ESP32-S3、Flash、PSRAM、Wi-Fi、Camera、Microphone、GPIO |
| 视觉目标发现与确认 | 确认入口、门牌、站点、服务设施及大致方位 | Camera、Wi-Fi |
| 标识与文字信息获取 | 读取门牌号、站名、入口与楼层标识 | Camera、Wi-Fi |
| 语音交互与反馈 | 通过自然语言提问并获得免手持反馈 | Microphone、Wi-Fi、外接 I2S 音频 |
| 状态与方向辅助提醒 | 断网、处理中、成功、左右方向等简洁提醒 | GPIO/PWM、振动模块，可选 LCD |

## ④ 各功能技术方案

1. **系统与设备能力验证（端侧）**：使用大赛分支现有 ESP32-S3-EYE openvela/NuttX BSP，验证 NSH、`wlan0`、V4L2、I2S、GPIO，并记录 CPU、内部 RAM、PSRAM、任务栈和碎片情况。
2. **视觉目标发现与确认（端云协同）**：通过 `/dev/video0` 按需取得单帧，经 JPEG 编码/提取后通过 Wi-Fi/HTTPS 上传 MiMo；设备端不持续上传视频，也不部署大型视觉模型。
3. **标识与文字信息获取（端侧采集、云端理解）**：端侧管理拍摄、裁剪和有界缓冲，MiMo 负责文字和场景语义理解，只返回当前问题需要的关键信息。
4. **语音交互（端云协同）**：板载麦克风采集 16 kHz/16 bit/单声道 PCM；ASR、视觉理解和自然语言生成在云端完成；TTS 经外接 I2S 音频模块播放。
5. **状态和方向反馈（端侧）**：第一阶段先以 NSH/控制台完成可审计反馈；随后用 GPIO/PWM 驱动振动模块，并增加音频反馈。

## 开发顺序

先完成“触发采图 → JPEG → 上传 → 解析 → 一种反馈”的 M1～M6 闭环，再扩展麦克风、ASR、TTS/I2S 的 M7～M10。各阶段只有在对应证据留存后才能从“待验证”改成“通过”。
